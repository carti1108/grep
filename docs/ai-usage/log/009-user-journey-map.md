# 2026-11-25 · 사용자 저니맵과 발표 슬라이드

- 이슈·PR: delightPIP/grep#3
- 커밋: 없음(커밋 전)

> **요약** PO가 서술한 사용자를 주인공으로 저니맵(가상 인물 3명, 공통 7단계)을 쓰고, 같은 내용을 발표용 슬라이드 14장으로 만들었다. 저니맵에서 원인 후보 N7(떠올리지 못함)과 결정적 순간 M1~M4, 기능 후보 F20·F21을 제안했고 PO 판단은 아직이다.

## 사용 도구

Claude Code(Claude Opus 5.5), it-service-planner 플러그인의 journey-map 스킬, Claude Slides 아티팩트.

## 요청

솔루션을 더 구체화하자며, 사용자의 라이프저니를 쓰고 표나 시각화로 그려 기획 자료와 발표 자료로 쓰게 해 달라고 했다. 사용자는 알고 싶은 게 많아 인스타그램·스레드·웹 검색에서 이것저것 저장하지만, 프로젝트에 적용하거나 Claude에 요청할 때는 그 자료를 떠올리지 못하고 같은 질문·검색을 반복하는 사람이라고 서술했다.

## AI 산출물

- `docs/planning/journey-map.md`: 인물 3명(주인공 서윤, 비교 민재, 반례 하린), 공통 7단계, 인물별 표, 감정 곡선(mermaid), 비교표, 원인 후보 N7, 결정적 순간 M1~M4와 해결안, 바뀐 뒤의 여정, 인터뷰·일지 확인 항목, 한계, PO 판단 항목 4개
- 발표 슬라이드 14장(Claude 아티팩트, 비공개)
- `STATE.md` 10절, `PRD.md` 9절에 저니맵 링크

## 사람의 판단

- 주인공의 행동과 문제(떠올리지 못해 같은 질문·검색을 반복)는 PO 서술이다
- 슬라이드에는 디자인 시스템을 적용하지 않음. 터미널 컨셉 디자인이 확정되면 그 design.md와 컴포넌트를 슬라이드에도 적용하기로 함
- N7, M2 해결안, 역할 나눔, F20·F21은 PO 판단 전

## 검증

`bash Scripts/check-docs.sh` 실행, 통과. 슬라이드는 화면 미리보기를 하지 못했다(브라우저 창에서 로그인이 필요했고 로컬 미리보기는 캡처가 안 됨). 비평 에이전트 검토는 하지 않았다.

## 검증하지 못한 것

1. 슬라이드 레이아웃(특히 감정 곡선 차트, 7칸 단계 줄)이 넘치지 않는지 눈으로 확인하지 않았다.
2. 인스타그램·스레드 게시물의 본문을 로그인 없이 가져올 수 있는지는 확인하지 않았다(개발자 확인 항목).

## 발견 사항

1. PO가 서술한 "잊음"은 이전 결정(해결 방향을 일반 재노출로 넓히지 않음)과 부딪힐 수 있어, 해결안을 모두 "AI 작업을 하는 순간에 넘기기를 돕는다"는 고정 솔루션 안에 두었다.
